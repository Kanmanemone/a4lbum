# Feature Specification: 압축만 풀면 쓰는 앨범 프로그램(exe + 대화창)

**Feature Branch**: `002-portable-album-app`

**Created**: 2026-10-06

**Status**: Draft

**Input**: User description: "받는 사람이 zip 압축만 풀면 Python 설치 없이 바로 쓸 수 있는 휴대용 앨범 프로그램. 압축을 풀면 exe 파일이 있고, exe를 클릭하면 간단한 대화창이 떠서 사진 폴더 경로를 고를 수 있고, 버튼을 누르면 기존 A4 앨범 PDF 생성 기능(001-a4-photo-album)과 같은 결과의 PDF가 만들어진다. 오버엔지니어링 금지."

## Clarifications

### Session 2026-10-07

- Q: (변경 요청) 사용자는 무엇을 받나? → A: 따로 만든 배포 zip이 아니라 GitHub 저장소 zip(Code → Download ZIP) 그대로다. 저장소 최상위에 미리 빌드한 `앨범 만들기.exe`와 실행에 필요한 `app\` 폴더를 커밋해 두어, 압축을 풀고 exe를 더블클릭하면 인터넷·Python·설치 없이 동작한다(stand-alone).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 압축 풀고 exe로 앨범 만들기 (Priority: P1)

컴퓨터에 익숙하지 않은 사용자가 GitHub에서 저장소 zip을 받아 압축을 푼다. 폴더 최상위의 앨범 프로그램(exe)을 더블클릭하면 작은 창이 뜬다. 창에서 사진 폴더를 고르고 "앨범 만들기"를 누르면, 001 기능과 같은 A4 앨범 PDF가 만들어진다. 창에 결과(저장 위치, 알림·경고)가 보이고, 버튼으로 PDF를 바로 열 수 있다.

**Why this priority**: 이 기능의 존재 이유다. 이것만으로 비개발자가 앨범을 만들 수 있다.

**Independent Test**: Python이 없는 Windows PC(또는 Python을 PATH에서 뺀 환경)의 빈 폴더에 zip을 풀고, exe를 실행해 사진 폴더를 골라 PDF가 만들어지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** zip을 압축 해제한 폴더, **When** 사용자가 exe를 더블클릭하면, **Then** 별도 설치나 검은 명령창 없이 대화창이 뜬다.
2. **Given** 대화창, **When** 사용자가 "찾아보기"로 사진 폴더를 고르면, **Then** 경로 칸에 그 폴더가 표시되고 저장될 PDF 경로(기본값)가 함께 보인다.
3. **Given** 사진 폴더가 선택된 상태, **When** "앨범 만들기"를 누르면, **Then** 001 기능과 같은 규칙(정렬, 메모 라벨, 형식 변환, 원본 보존)으로 PDF가 만들어지고, 창에 "완료: 사진 N장 → P페이지"와 알림·경고 줄이 표시된다.
4. **Given** 만들기가 끝난 상태, **When** "PDF 열기"를 누르면, **Then** 기본 PDF 뷰어로 만들어진 PDF가 열린다.
5. **Given** 같은 사진 폴더와 같은 출력 경로, **When** exe로 만든 PDF와 스크립트(001)로 만든 PDF를 비교하면, **Then** 페이지 수, 사진 배치, 라벨 내용이 같다.

---

### User Story 2 - 문제 상황을 창에서 바로 이해하기 (Priority: P2)

폴더를 고르지 않았거나, 사진이 없거나, PDF가 다른 프로그램에서 열려 있어 저장할 수 없을 때, 사용자는 창 안에서 무엇이 문제인지 한국어로 안내받는다. 프로그램이 멈추거나 조용히 꺼지지 않는다.

**Why this priority**: 비개발자는 명령창 오류를 볼 수 없으므로 창 안 안내가 필요하다. 다만 기본 흐름이 먼저다.

**Independent Test**: 빈 폴더를 골라 "앨범 만들기"를 누르고, 창에 "넣을 사진이 없습니다" 안내가 보이며 창이 계속 쓸 수 있는 상태인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사진 폴더를 고르지 않은 상태, **When** "앨범 만들기"를 누르면, **Then** 폴더를 먼저 고르라는 안내가 보이고 아무 파일도 만들지 않는다.
2. **Given** 사진이 없거나 모두 열 수 없는 폴더, **When** "앨범 만들기"를 누르면, **Then** 파일별 경고와 "넣을 사진이 없습니다" 오류가 창에 보인다.
3. **Given** 출력 PDF가 PDF 뷰어에서 열려 있는 상태, **When** "앨범 만들기"를 누르면, **Then** "PDF 뷰어를 닫고 다시 실행" 안내가 창에 보인다.
4. **Given** 사진이 많아 시간이 걸리는 상황, **When** 만드는 중이면, **Then** 창이 "만드는 중…" 상태를 보이고 응답 없음으로 멈추지 않으며, 끝나기 전에는 버튼을 다시 누를 수 없다.

---

### User Story 3 - 저장소의 exe 다시 만들기 (Priority: P3)

프로젝트 관리자(사용자 본인)는 코드를 바꾼 뒤 명령 한 번으로 저장소 최상위의 `앨범 만들기.exe`와 `app\`을 다시 만들어 커밋한다.

**Why this priority**: 받는 사람에게 전달하려면 필요하지만, 관리자가 가끔 실행하는 작업이다.

**Independent Test**: 빌드 명령을 실행해 exe와 `app\`이 바뀌고, 저장소를 zip으로 묶어 다른 폴더에 풀었을 때 US1 시나리오가 통과하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 개발 환경, **When** 관리자가 빌드 명령 하나를 실행하면, **Then** 저장소 최상위의 `앨범 만들기.exe`와 `app\`이 새 코드로 바뀐다.
2. **Given** 그 상태의 저장소 zip(GitHub Download ZIP과 같은 것), **When** 다른 경로(한글·공백 포함 경로 포함)에 풀면, **Then** exe가 정상 실행되고 HEIC 변환까지 포함해 PDF가 만들어진다.

---

### Edge Cases

- exe가 한글이나 공백이 들어간 경로(예: `C:\Users\홍길동\바탕 화면\앨범 프로그램`)에 풀려 있을 때도 동작한다.
- 사진 폴더 경로나 파일 이름에 한글·공백·이모지가 있어도 동작한다.
- 사용자가 저장 위치를 바꾸지 않으면 001과 같은 기본 위치(`<사진 폴더 부모>/<폴더이름>_album.pdf`)에 저장한다.
- 사용자가 사진 폴더를 다시 고르면, 저장 위치를 직접 바꾸지 않은 한 기본 저장 경로도 새 폴더에 맞춰 바뀐다.
- 사진 폴더를 exe 아이콘 위로 끌어다 놓아 실행하면, 그 폴더가 미리 선택된 상태로 창이 뜬다.
- 만들기 도중 창을 닫으면, 만들던 PDF 조각(임시 파일)이 남지 않는다.
- 압축을 풀지 않고 zip 안에서 바로 exe를 실행하면 동작을 보장하지 않는다. README 사용법에 "압축 풀기"를 단계로 적는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 배포 묶음은 압축 해제만으로 실행할 수 있어야 MUST 한다. 받는 사람의 PC에 Python, 추가 패키지, 인터넷 연결이 필요 없어야 한다.
- **FR-002**: 배포 묶음 최상위에 더블클릭으로 실행하는 exe 파일 하나가 있어야 MUST 하며, 실행 시 명령창(콘솔) 없이 대화창만 떠야 한다.
- **FR-003**: 대화창은 사진 폴더 경로 칸 + "찾아보기" 버튼, 저장할 PDF 경로 칸 + "찾아보기" 버튼, "앨범 만들기" 버튼, 결과 표시 영역, "PDF 열기" 버튼을 가져야 MUST 한다. 그 밖의 설정은 두지 않는다.
- **FR-004**: 앨범 내용(정렬, 배치, 메모 라벨, 형식 변환, 경고·알림 문구, 원본 보존)은 001 기능의 규칙과 같아야 MUST 하며, 별도로 다시 구현하지 않고 001의 동작을 그대로 사용해야 한다.
- **FR-005**: 결과 표시 영역에는 001의 표준 출력과 같은 내용(알림·경고 줄, 완료 요약, PDF 경로)과 오류 안내를 보여야 MUST 한다.
- **FR-006**: 만드는 동안 창은 응답 상태를 유지하고, "앨범 만들기" 버튼은 끝날 때까지 비활성화되어야 MUST 한다.
- **FR-007**: "PDF 열기" 버튼은 PDF가 성공적으로 만들어진 뒤에만 활성화되고, 누르면 PC의 기본 PDF 뷰어로 열어야 MUST 한다.
- **FR-008**: exe에 사진 폴더 경로가 인자로 주어지면(폴더를 exe에 끌어다 놓기) 그 폴더를 미리 선택해 창을 띄워야 MUST 한다. 자동으로 만들기를 시작하지는 않는다.
- **FR-009**: 관리자는 명령 하나로 저장소 최상위의 `앨범 만들기.exe`와 `app\`을 다시 만들 수 MUST 있다. 이 둘은 저장소에 커밋되어, 저장소 zip을 받은 사용자가 별도 다운로드 없이 바로 쓴다.
- **FR-010**: 빌드 과정은 배포 묶음이 실제로 앨범을 만들 수 있는지(HEIC 변환 포함) 자동으로 확인하고, 실패하면 저장소의 exe와 `app\`을 바꾸지 않아야 MUST 한다.

### Key Entities

- **배포 묶음**: 저장소 최상위의 `앨범 만들기.exe`와 실행에 필요한 파일이 든 `app\` 폴더. 사용자는 저장소 zip으로 받는다.
- **대화창 상태**: 사진 폴더 경로, 저장 PDF 경로(기본값 자동 / 사용자 지정), 진행 중 여부, 마지막 결과(성공 시 PDF 경로, 출력 줄들).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Python이 설치되지 않은 Windows 10/11 PC에서, 압축 해제부터 첫 PDF 생성까지 사용자 조작이 "압축 풀기 → exe 더블클릭 → 폴더 고르기 → 앨범 만들기" 4단계 이내다.
- **SC-002**: exe를 더블클릭하고 대화창이 보이기까지 10초 이내다.
- **SC-003**: 같은 사진 폴더로 exe와 001 스크립트가 만든 PDF는 페이지 수, 페이지마다의 사진 수·위치, 라벨 문구가 100% 같다.
- **SC-004**: US2의 오류 상황 4가지 모두에서 창이 꺼지거나 응답 없음 상태가 되지 않고, 한국어 안내가 표시된다.
- **SC-005**: 저장소 zip은 한글·공백이 들어간 경로에 풀어도 HEIC가 포함된 사진 폴더로 PDF를 만든다.

## Assumptions

- 받는 사람은 64비트 Windows 10/11 사용자다. Mac·Linux용 묶음은 범위 밖이다.
- 라벨 글꼴은 001과 같이 Windows 기본 글꼴(맑은 고딕)을 사용하므로 배포 묶음에 글꼴을 넣지 않는다.
- exe는 코드 서명을 하지 않는다. 처음 실행할 때 Windows SmartScreen이 "알 수 없는 게시자" 경고를 띄울 수 있으며, 사용법 안내에 "추가 정보 → 실행" 방법을 적는다.
- 배포 묶음은 저장소에 커밋하지 않고 빌드할 때마다 새로 만든다.
- 대화창 문구는 한국어만 지원한다.
- 001의 명령줄 실행과 `/album` 스킬은 그대로 유지한다.
- 설치 프로그램(인스톨러), 자동 업데이트, 시작 메뉴 등록, 여러 폴더 동시 처리, 레이아웃 설정 UI는 범위 밖이다.
