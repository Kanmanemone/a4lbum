# Research: 앨범 창에서 사진 파일 이름 바꾸기

## R1. 편집을 여는 방법

- **Decision**: 이름을 두 번 클릭하면 같은 칸에 입력 칸을 띄운다. 목록 위에 안내 문구를 둔다.
- **Rationale**: 줄마다 이미 버튼이 4개라 "이름 바꾸기" 버튼을 더하면 줄이 넓어진다. 탐색기처럼 그 자리에서 고치는 것이 익숙하다.
- **Alternatives considered**: 줄마다 버튼 + 입력 대화상자는 줄 폭과 클릭 수가 늘어 탈락했다.

## R1a. 입력 칸 자리 (변경 요청)

- **Decision**: 순번과 이름은 그대로 라벨 하나에 두고, 입력 칸을 같은 칸에 놓되 왼쪽 여백(`padx`)을 라벨 글꼴로 잰 순번 부분(`"  1   "`) 폭만큼 준다.
- **Rationale**: 순번을 별도 라벨로 나누면 열 구성과 목록 갱신 코드가 바뀐다. 여백 한 줄이면 같은 결과다.
- **Alternatives considered**: 순번 전용 열은 변경이 커서 탈락했다.

## R2. 확장자

- **Decision**: 입력 칸에는 확장자를 뺀 이름만 보이고, 원래 확장자를 그대로 붙인다.
- **Rationale**: 바꾸고 싶은 것은 라벨 문구(확장자 뺀 이름)다. 확장자가 바뀌면 사진이 목록에서 사라질 수 있다.

## R3. 안전 검사

- **Decision**: `\ / : * ? " < > |`가 있으면 `ValueError`. 존재 여부를 미리 보지 않고 `os.rename`에 맡긴다. Windows의 `os.rename`은 대상이 있으면 `FileExistsError`를 내고 덮어쓰지 않으며, 대소문자만 다른 이름으로는 바꿔 준다.
- **Rationale**: `/`·`\`가 있으면 다른 폴더로 옮겨질 수 있어 막아야 한다. 미리 `exists()`로 보면 대소문자 무시 파일 시스템에서 대소문자만 바꾸는 것까지 막힌다.
- **Alternatives considered**: `os.replace`는 덮어써서 탈락했다.

## R4. 바꾼 뒤 목록

- **Decision**: `self.photos[index]`의 이름만 바꾸고(날짜·촬영 시각 유지), 커스텀이 아니면 `resort()`. 실패하면 폴더를 다시 읽는다(`load_photos`). 다시 읽으면 커스텀 순서가 사라지지만, 파일이 사라지는 등 드문 경우라 받아들인다.
- **Rationale**: 이름 바꾸기는 파일 날짜를 바꾸지 않으므로 다시 읽을 필요가 없다. "이름 순 정렬"인데 순서가 어긋나 보이지 않게 다시 정렬한다.
