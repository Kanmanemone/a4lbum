# Feature Specification: A4 사진 앨범 페이지 만들기

**Feature Branch**: `001-a4-photo-album`

**Created**: 2026-10-06

**Status**: Draft

**Input**: User description: "사진과 사진마다의 설명을 넣으면, 그걸 a4 용지 인쇄하여, a4 파일에 넣으면 앨범처럼 보이게하는 프로그램 만들고싶어. 거창한 exe 만드는건 좀 그렇고, 그냥 프롬프트 및 스크립트 몇개로 해결하고싶어. 일반 앨범 형식은 단순하게 할거야. a4 위 아래 각각에 사진 한장씩 들어가게. 그리고, 사진 마다 오른쪽 위 모서리 쪽에 사진 설명이 들어가는거지."

## Clarifications

### Session 2026-10-06

- Q: 각 사진의 설명을 사진 위에 겹쳐 올릴까요, 아니면 사진 바깥 오른쪽 위 여백에 둘까요? → A: 사진 오른쪽 위 모서리에 걸친 메모 라벨 형태(라벨 일부만 사진에 겹침)
- Q: 사진과 설명을 어떤 방식으로 짝지어 넣을까요? → A: 사진 파일 이름 자체에 설명을 적는다. 앨범 순서는 파일 이름순이고, 이름이 "숫자_텍스트" 형식이면 "숫자_"를 뺀 "텍스트"만 메모 라벨에 넣는다(예: "283_벚꽃 축제 모습.jpg" → "벚꽃 축제 모습").
- Q: 사진 비율이 칸 모양과 다를 때 잘라서 꽉 채울까요, 자르지 않고 통째로 넣을까요? → A: 자르지 않는다. 사진 전체를 비율 그대로 칸 안에 맞추고 칸 안에서 가운데 정렬하며, 남는 공간은 여백으로 둔다.
- Q: 완성된 앨범을 어떤 형태로 받아서 인쇄할까요? → A: 앨범 전체가 담긴 PDF 파일 1개. 사진은 원본 화질 그대로(축소·재압축 없이) 넣는다.
- Q: 앨범 생성은 Claude 지시로만 할까요, Claude 없이 스크립트를 직접 실행할 수도 있어야 할까요? → A: 둘 다. 스크립트가 본체이고, Claude 지시(예: `/album <폴더>`)는 그 스크립트를 대신 실행해 주는 바로가기다.
- Q: (변경 요청) 메모 라벨 배경색은? → A: 흰색.
- Q: (변경 요청) 파일 이름 맨 앞이 "숫자_"가 아니라 그냥 숫자로 시작하면? → A: 제거하지 않는다. "숫자_"(밑줄 포함)일 때만 뗀다(예: "2026여행.jpg" → "2026여행").
- Q: (변경 요청) HEIC 사진이 있으면? → A: 건너뛰지 않고 스크립트가 JPEG로 변환해 앨범에 넣는다. 변환본은 임시 폴더에만 만들고 원본 폴더는 건드리지 않는다.
- Q: (변경 요청) WEBP, GIF, BMP, TIFF 등은? → A: 모두 변환해 넣는다. 사진은 JPEG(품질 95), 색 256개 이하 그래픽·투명 배경 이미지는 PNG(무손실)로 바꾼다(비교 근거: research R7).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사진과 설명으로 인쇄용 앨범 페이지 만들기 (Priority: P1)

사용자는 앨범에 넣을 사진들을 한 폴더에 모으고, 각 사진의 파일 이름을 "숫자_설명" 형식(예: "283_벚꽃 축제 모습.jpg")으로 바꿔 둔 뒤 그 폴더를 도구에 넘긴다. 도구는 A4 한 장에 사진 두 장(위 한 장, 아래 한 장)을 배치하고, 각 사진의 오른쪽 위 모서리 쪽에 그 사진의 설명을 넣은 앨범 PDF를 만든다. 사용자는 이 문서를 집 프린터로 A4에 인쇄해 A4 클리어 파일(포켓 파일)에 끼우면 앨범처럼 넘겨 볼 수 있다.

**Why this priority**: 이 기능의 존재 이유 자체다. 이것만 있어도 사용자는 완성된 앨범을 만들 수 있다.

**Independent Test**: "숫자_설명" 형식 이름의 사진 4장이 든 폴더로 실행하고, 결과물이 A4 2페이지이며 각 페이지에 사진 2장과 각 사진의 설명이 정해진 위치에 있는지 인쇄 미리보기로 확인한다.

**Acceptance Scenarios**:

1. **Given** 폴더에 "숫자_설명" 형식 이름의 사진 4장이 있을 때, **When** 사용자가 앨범 생성을 실행하면, **Then** A4 세로 2페이지짜리 앨범 PDF가 만들어지고 각 페이지 위쪽 절반과 아래쪽 절반에 사진이 한 장씩 들어간다.
2. **Given** 생성된 문서를 볼 때, **When** 각 사진을 확인하면, **Then** 사진마다 그 사진에 해당하는 설명이 사진 오른쪽 위 모서리에 걸친 메모 라벨로 표시되고, 라벨은 일부만 사진에 겹친다.
3. **Given** 폴더에 "2_바다.jpg", "10_산.jpg", "1_집.jpg"가 있을 때, **When** 문서를 확인하면, **Then** 사진은 파일 이름순(앞 숫자는 숫자 크기순)인 "집 → 바다 → 산" 순서로 1페이지 위, 1페이지 아래, 2페이지 위에 배치된다.
4. **Given** 사진 파일 이름이 "283_벚꽃 축제 모습.jpg"일 때, **When** 문서를 확인하면, **Then** 그 사진의 메모 라벨에는 "벚꽃 축제 모습"만 적혀 있다(앞의 "283_"와 확장자 ".jpg"는 나오지 않음).
5. **Given** 생성된 문서를 실제 A4 용지에 100% 배율로 인쇄했을 때, **When** 인쇄물을 확인하면, **Then** 사진과 설명이 잘리지 않고 용지 안에 모두 들어간다.

### User Story 2 - 복잡한 설치 없이 간단히 실행하기 (Priority: P2)

사용자는 별도의 설치형 프로그램이나 실행 파일 없이 앨범 PDF를 만든다. 실행 방법은 두 가지다. 터미널에서 스크립트를 직접 실행하거나, Claude Code에서 지시 한 줄로 같은 스크립트를 대신 실행하게 한다. 두 방법은 같은 결과물을 만든다. 사진을 추가하거나 파일 이름(설명)을 고친 뒤 다시 실행하면 PDF가 새로 만들어진다.

**Why this priority**: 사용자가 명시적으로 원한 사용 방식이다. 다만 핵심 결과물(P1) 없이는 의미가 없으므로 두 번째 우선순위다.

**Independent Test**: 새 PC 환경에서 안내 문서에 적힌 절차만 따라 사진 2장으로 앨범 문서를 만들어 본다.

**Acceptance Scenarios**:

1. **Given** 사진 폴더가 준비된 상태에서, **When** 사용자가 Claude 없이 터미널에서 안내된 스크립트 명령 하나를 실행하면, **Then** 추가 조작 없이 앨범 PDF가 만들어진다.
2. **Given** 이미 문서를 한 번 만든 상태에서, **When** 사진 하나의 파일 이름(설명)을 고치고 다시 실행하면, **Then** 고친 설명이 반영된 문서가 다시 만들어진다.
3. **Given** 같은 사진 폴더로, **When** 사용자가 Claude Code에서 지시 한 줄(예: `/album <폴더>`)을 실행하면, **Then** 스크립트를 직접 실행했을 때와 같은 내용의 앨범 PDF가 만들어지고, 경고가 있으면 Claude가 그대로 전달한다.

---

### User Story 3 - 입력 문제를 알아차리기 (Priority: P3)

폴더 안의 사진 파일을 열 수 없거나, 파일 이름에 설명이 빠졌거나 너무 길 때, 사용자는 어떤 사진에 무슨 문제가 있는지 알림을 받는다.

**Why this priority**: 인쇄 전에 실수를 잡아 용지 낭비를 줄여 주지만, 기본 흐름이 먼저다.

**Independent Test**: 깨진 사진 파일 하나와 이름이 "7_.jpg"처럼 설명이 빠진 사진 하나를 섞어 실행하고, 두 문제가 각각 파일 이름과 함께 보고되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 폴더에 열 수 없는(깨진) 사진 파일이 하나 있을 때, **When** 실행하면, **Then** 해당 파일 이름과 문제 내용이 사용자에게 알려지고 나머지 사진으로 문서가 만들어진다.
2. **Given** 설명이 지정된 최대 길이를 넘을 때, **When** 실행하면, **Then** 해당 사진이 경고로 보고된다.

---

### Edge Cases

- 사진 수가 홀수일 때: 마지막 페이지는 위쪽에만 사진이 들어가고 아래쪽은 비워 둔다.
- 사진이 1장뿐일 때: 위쪽에 사진이 들어간 1페이지 문서가 만들어진다.
- 사진이 0장일 때: 문서를 만들지 않고 "넣을 사진이 없다"고 알린다.
- 세로로 긴 사진일 때: 비율을 유지한 채 할당된 절반 칸 안에 맞춰 줄여 넣고 가운데 정렬한다(잘라내지 않음). 양옆에 남는 공간은 여백으로 둔다. 메모 라벨은 칸이 아니라 실제 사진의 오른쪽 위 모서리를 기준으로 붙는다.
- 파일 이름이 "숫자_" 형식이 아닐 때(예: "벚꽃.jpg"): 확장자를 뺀 이름 전체("벚꽃")를 설명으로 쓰고, 정렬은 이름순을 따른다.
- 파일 이름이 밑줄 없이 숫자로 시작할 때(예: "2026여행.jpg", "5월 소풍.jpg"): 숫자를 떼지 않고 이름 전체("2026여행", "5월 소풍")를 설명으로 쓴다.
- JPEG·PNG가 아닌 사진(HEIC/HEIF, AVIF, WEBP, GIF, BMP, TIFF): 변환해 넣고, 변환했다는 알림을 파일 이름과 함께 보여 준다(경고 건수에는 넣지 않음). 변환할 수 없는 파일이면 "열 수 없는 사진" 경고 후 건너뛴다.
- 움직이는 GIF/WEBP, 여러 장이 든 TIFF: 첫 장면만 넣고 알림에 그 사실을 적는다.
- 확장자와 실제 형식이 다를 때(예: 내용은 WEBP인 ".jpg"): 실제 형식을 기준으로 처리한다. 휴대폰이 만드는 MPO(여러 장이 든 JPEG)는 JPEG로 보고 변환 없이 넣는다.
- 카메라 RAW 파일(CR2, NEF, ARW, DNG 등): 지원하지 않는다는 경고 후 건너뛴다.
- 설명 텍스트 안에 밑줄이 있을 때(예: "3_엄마_아빠.jpg"): 맨 앞의 "숫자_"만 떼고 나머지("엄마_아빠")는 그대로 둔다.
- 파일 이름이 "숫자_"뿐이라 설명이 비어 있을 때(예: "7_.jpg"): 메모 라벨 없이 사진만 배치하고 경고로 알린다.
- 앞 숫자가 같은 사진이 여럿일 때: 숫자 뒤 텍스트의 이름순으로 정렬한다.
- 폴더 안에 사진이 아닌 파일(문서, 숨김 파일 등)이 있을 때: 무시한다.
- 설명이 길 때: 메모 라벨 안에서 여러 줄로 줄바꿈하며, 최대 길이를 넘으면 경고한다. 라벨이 커지더라도 가리는 사진 면적 상한(FR-005)을 넘지 않는다.
- 사진이 칸 너비를 꽉 채울 때: 라벨이 사진 바깥으로 나올 자리가 남도록 사진 크기를 줄여, 라벨이 페이지 밖으로 잘리지 않게 한다.
- 한글·이모지 등이 포함된 설명: 글자가 깨지지 않고 표시된다.
- 해상도가 매우 낮은 사진: 그대로 배치하되 인쇄 시 흐릿할 수 있음을 경고한다.
- 휴대폰 사진의 회전 정보: 촬영 방향대로 바르게 세워진 상태로 배치된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 사진들이 든 폴더 하나를 지정해 입력할 수 MUST 있다. 각 사진의 설명은 그 사진의 파일 이름에서 얻는다.
- **FR-001a**: 시스템은 파일 이름(확장자 제외)이 "숫자_텍스트" 형식이면 맨 앞의 "숫자_"를 제거한 "텍스트"를 설명으로 사용해야 MUST 한다(예: "283_벚꽃 축제 모습.jpg" → "벚꽃 축제 모습"). 이 형식이 아니면 확장자를 뺀 파일 이름 전체를 설명으로 사용한다.
- **FR-002**: 시스템은 A4 세로 크기(210mm × 297mm)의 페이지로 이루어진 PDF 파일 1개를 만들어야 MUST 한다. 이 PDF를 "실제 크기(100%)"로 인쇄하면 페이지가 A4에 1:1로 맞는다.
- **FR-002a**: 시스템은 사진을 원본 화질 그대로(해상도 축소나 재압축 없이) PDF에 넣어야 MUST 하며, 원본 사진 파일은 읽기만 하고 수정·이동·삭제하지 않아야 MUST 한다. 예외: PDF에 그대로 넣을 수 없는 형식은 한 번 변환해 넣는다(FR-014).
- **FR-003**: 시스템은 페이지마다 위쪽 절반과 아래쪽 절반에 사진을 한 장씩, 최대 두 장을 배치해야 MUST 한다.
- **FR-004**: 시스템은 사진을 파일 이름순으로 배치해야 MUST 한다. 이름 앞의 숫자는 글자순이 아니라 숫자 크기순으로 비교한다(예: "2_…"가 "10_…"보다 앞).
- **FR-005**: 시스템은 각 사진의 설명을 해당 사진의 오른쪽 위 모서리에 걸친 메모 라벨(흰색 불투명 바탕에 옅은 회색 테두리·그림자를 둔 작은 라벨)로 표시해야 MUST 한다. 라벨은 일부만 사진에 겹치고 나머지는 사진 바깥 여백으로 나오며, 라벨 전체(글씨 포함)가 페이지의 인쇄 가능 영역 안에 있어야 한다. 라벨이 가리는 사진 면적은 사진 전체 면적의 15% 이하여야 한다.
- **FR-006**: 시스템은 사진의 원래 가로세로 비율을 유지하고, 사진을 잘라내지 않고 할당된 칸 안에 들어가는 최대 크기로 맞춰 칸 안에서 가운데 정렬해야 MUST 한다. 남는 공간은 여백으로 둔다.
- **FR-007**: 시스템은 모든 내용(사진, 설명)을 일반 가정용 프린터의 인쇄 가능 영역 안에 두어야 MUST 한다(각 변 최소 10mm 여백).
- **FR-008**: 시스템은 사진 수가 홀수일 때 마지막 페이지의 아래쪽을 비워 두어야 MUST 한다.
- **FR-009**: 시스템은 열 수 없는 사진, 비어 있는 설명, 최대 길이를 넘는 설명을 파일 이름과 함께 사용자에게 알려야 MUST 한다.
- **FR-010**: 시스템은 문제가 있는 사진을 건너뛰고 나머지 사진으로 문서를 완성해야 MUST 한다.
- **FR-011**: 사용자는 별도 설치형 프로그램 없이, 사진 폴더를 지정한 스크립트 명령 하나로 앨범 PDF를 만들 수 MUST 있다. 이 방법은 Claude 없이도 동작해야 한다.
- **FR-011a**: 사용자는 Claude Code에서 지시 한 줄로 FR-011의 스크립트를 실행할 수 MUST 있다. 이 지시는 스크립트를 대신 실행하고 결과(PDF 위치, 경고)를 전달할 뿐, 앨범 내용을 다르게 만들지 않는다.
- **FR-012**: 시스템은 한글 설명을 깨짐 없이 표시해야 MUST 한다.
- **FR-013**: 시스템은 촬영 기기에 기록된 회전 정보를 반영해 사진을 바른 방향으로 배치해야 MUST 한다.
- **FR-014**: 시스템은 JPEG·PNG가 아닌 사진(HEIC/HEIF, AVIF, WEBP, GIF, BMP, TIFF)을 발견하면 건너뛰지 않고 변환해 다른 사진과 똑같이 배치해야 MUST 한다. 사진은 JPEG(품질 95), 색이 256개 이하이거나 투명 부분이 있는 이미지는 PNG(무손실)로 바꾼다. 변환본은 임시 폴더에만 만들고 실행이 끝나면 지우며, 변환 사실을 파일 이름과 함께 알려야 한다.

### Key Entities

- **사진 항목**: 앨범에 들어갈 사진 한 장. 사진 파일 하나이며, 그 파일 이름에서 설명과 앨범 내 순서(파일 이름순)가 정해진다.
- **설명**: 사진 한 장에 붙는 짧은 글. 파일 이름에서 확장자와 앞의 "숫자_"를 뺀 텍스트이며 사진 오른쪽 위 모서리에 걸친 메모 라벨로 표시된다.
- **앨범 페이지**: A4 세로 한 장. 위 칸과 아래 칸, 두 개의 사진 칸을 가진다.
- **앨범 PDF**: 앨범 페이지들을 순서대로 묶은 인쇄용 결과물(PDF 파일 1개).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사진 N장을 입력하면 정확히 ⌈N/2⌉ 페이지의 문서가 만들어진다.
- **SC-002**: 사진과 설명을 준비한 뒤 앨범 PDF를 얻기까지 사용자의 조작이 1회 실행(스크립트 명령 1개 또는 Claude 지시 1개)으로 끝나며, 두 방법의 결과 PDF는 페이지 구성·사진·라벨 내용이 같다.
- **SC-003**: 사진 20장 기준으로 문서가 1분 이내에 만들어진다.
- **SC-004**: 100% 배율로 A4에 인쇄했을 때 사진·설명이 잘리는 페이지가 0장이다.
- **SC-005**: 인쇄물을 A4 클리어 파일에 넣었을 때 모든 페이지에서 사진 두 장과 각 메모 라벨이 파일 테두리나 가장자리에 가려지지 않고 보인다.
- **SC-006**: 입력 문제(열 수 없는 사진, 빈 설명, 너무 긴 설명)가 있을 때 100% 파일 이름과 함께 보고된다.
- **SC-007**: PDF 안의 각 사진은 원본 사진과 픽셀 크기가 같다(JPEG·PNG는 화질 손실 0, 그 밖의 형식은 변환: 사진은 품질 95 JPEG, 그래픽은 무손실 PNG). 실행 전후로 원본 사진 파일의 내용이 바뀌지 않는다.

## Assumptions

- 사용자는 앨범을 직접 만드는 개인 1명이며, 여러 사용자나 공유 기능은 필요 없다.
- 설명은 사용자가 사진 파일 이름에 직접 적는다. 사진을 보고 설명을 자동으로 지어 주는 기능이나 별도의 설명 목록 파일은 이번 범위에 포함하지 않는다.
- 파일 이름에 쓸 수 없는 문자(\ / : * ? " < > | 등)는 설명에도 쓸 수 없다는 제약을 받아들인다.
- 한 번 실행에는 사진 폴더 하나를 대상으로 하며, 하위 폴더는 살펴보지 않는다.
- 사진 형식은 휴대폰·디지털카메라에서 흔히 쓰는 일반 이미지 형식(JPEG, PNG, HEIC/HEIF, AVIF, WEBP, GIF, BMP, TIFF)을 대상으로 한다. 카메라 RAW는 범위 밖이다.
- 결과물은 PDF 파일이며, 인쇄 자체는 사용자가 평소 쓰는 PDF 뷰어의 인쇄 기능("실제 크기")으로 한다.
- 사진을 원본 화질로 넣으므로 PDF 용량은 원본 사진 용량 합계와 비슷해진다(예: 휴대폰 사진 20장 ≈ 수십 MB). 가정 인쇄용으로는 문제없는 크기로 본다.
- A4 클리어 파일은 용지 전체를 덮는 비닐 포켓 형태라 펀치 구멍용 여백은 따로 두지 않는다.
- 페이지마다 독립적으로 구성되므로 단면·양면 인쇄 어느 쪽이든 쓸 수 있다.
- 설명은 한 사진당 최대 3줄(약 60자) 정도의 짧은 글을 기본으로 가정하며, 이를 넘으면 경고한다.
- 레이아웃은 한 가지(위아래 1장씩)만 제공하며, 페이지 꾸미기·테마·표지·사진 편집(자르기, 보정)은 범위 밖이다.
